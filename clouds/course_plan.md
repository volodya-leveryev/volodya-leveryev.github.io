# Курс «Облачные технологии»: обновлённый план (7 лекций + 21 практическая работа)

## 0. Логика изменений (кратко)

Текущий курс сильный по AWS-«механике» (EC2, S3, RDS, DynamoDB, Lambda, Fargate, Terraform), но для трека **Data Engineer / Data Scientist** не хватает трёх вещей:

1. **Данные как первый класс** — нет ни одной работы про ETL/ELT, оркестрацию данных, потоковую обработку, аналитические СУБД (Athena/Redshift, BigQuery). Это ядро профессии DE.
2. **Практика сети и безопасности** — есть лекция про VPC, но нет ни одной лабораторной работы, где студент сам строит VPC, подсети, security groups; нет лабы по IAM-политикам как отдельному навыку.
3. **FinOps и мониторинг** — есть лекция про стоимость AWS, но нет практики (Cost Explorer, Budgets, CloudWatch), а это ежедневная работа инженера в облаке.

Также два лабораторных занятия (GitHub Pages, Firebase) слабо связаны с целевыми профессиями и частично дублируют друг друга (обе — про простой хостинг) — предлагается объединить их в одну работу и высвободить место для аналитических тем.

**Общий принцип реорганизации**: двигаться по возрастанию сложности и по логике реального пайплайна данных —
`инфраструктура → вычисления и сети → хранение → обработка/аналитика данных → оркестрация → ML/MLOps → безопасность и стоимость`,
и на каждом шаге чередовать AWS и GCP, чтобы к концу курса студент свободно сопоставлял сервисы двух провайдеров (важный навык для DE/DS, которые редко работают только с одним облаком).

## 1. Лекции (7 шт.)

### Лекция 1. Введение в облачные вычисления
**Цель**: дать понятийный каркас на весь курс.
- Что такое cloud computing, история перехода от on-premise к облаку.
- Модели обслуживания: IaaS / PaaS / SaaS / FaaS (с примерами сервисов AWS и GCP на каждый уровень).
- Модели развёртывания: public / private / hybrid / multi-cloud.
- Преимущества и риски облака: эластичность, pay-as-you-go, vendor lock-in, соответствие требованиям (GDPR, 152-ФЗ).
- Роли в облачном проекте: Cloud/DevOps Engineer, Data Engineer, Data Scientist/ML Engineer — чем они отличаются в облачном контексте (задел для мотивации всего курса).

*(новый материал — расширяет прежнее отсутствующее вводное занятие; раньше курс сразу начинался с инфраструктуры)*

### Лекция 2. Облачная инфраструктура провайдеров
На основе существующей лекции «Облачная инфраструктура», дополнить:
- Регионы, зоны доступности, дата-центры, партишены (как сейчас).
- Edge locations / points of presence (важно для CloudFront/CDN, изучаемого в лабе 6).
- Соответствие терминов AWS ↔ GCP ↔ Azure (Region/Zone, Project/Account, Availability Domain).
- Критерии выбора региона: задержка, стоимость, доступность сервисов, требования резидентности данных.

### Лекция 3. Обзор провайдеров и облачных сервисов
Объединение прежних лекций «Обзор провайдеров» + «Обзор облачных сервисов»:
- Крупнейшие провайдеры: AWS, GCP, Azure, доли рынка, специфика позиционирования.
- Сравнительная таблица сервисов по категориям: Compute, Storage, Database, Networking, Analytics/Big Data, ML/AI, Security.
- «Розеттский камень» AWS ↔ GCP (EC2/Compute Engine, S3/Cloud Storage, RDS/Cloud SQL, Lambda/Cloud Functions, Redshift/BigQuery и т.д.) — таблица, к которой студенты возвращаются весь курс.
- Как выбирать провайдера и сервис под задачу (чек-лист).

### Лекция 4. Вычисления и сети в облаке
Слияние «Amazon EC2» + «AWS VPC», с добавлением спектра вычислительных моделей:
- Спектр Compute: VM (EC2/Compute Engine) → контейнеры (Fargate/Cloud Run) → serverless-функции (Lambda/Cloud Functions) — когда что выбирать.
- Типы и семейства инстансов, спотовые инстансы, автомасштабирование (теория к лабам 4–5, 11).
- Сетевая модель облака: VPC, подсети (public/private), route tables, Internet Gateway/NAT, Security Groups vs NACL.
- Балансировка нагрузки (ALB/NLB), основы отказоустойчивой архитектуры.

### Лекция 5. Хранение данных и базы данных в облаке
Новая лекция — фундамент для DE/DS трека:
- Классы хранилищ: объектное (S3/GCS), блочное (EBS/Persistent Disk), файловое (EFS/Filestore); storage classes и жизненный цикл данных (Hot/Warm/Cold/Archive).
- Реляционные БД как сервис (RDS/Cloud SQL) vs NoSQL (DynamoDB/Firestore) — модели данных, когда что использовать.
- Понятия Data Lake vs Data Warehouse vs Lakehouse; место S3+Athena / BigQuery / Redshift в этой картине.
- Форматы хранения аналитических данных: CSV/JSON vs колоночные (Parquet, ORC) — почему это важно для стоимости и скорости запросов.

### Лекция 6. Обработка данных и аналитика в облаке (Data Engineering)
Новая лекция — ядро для будущих Data Engineer:
- ETL vs ELT, batch vs streaming обработка.
- Инструменты AWS: Glue (ETL + Data Catalog), Athena (serverless SQL), EMR (Spark/Hadoop, обзорно), Kinesis (потоковые данные).
- Инструменты GCP: Dataflow, BigQuery, Pub/Sub — параллели с AWS.
- Оркестрация пайплайнов: Step Functions, AWS MWAA / Cloud Composer (managed Airflow), Apache Airflow как индустриальный стандарт.
- Пример типового пайплайна данных «от источника до дашборда».

### Лекция 7. Безопасность, стоимость и ML в облаке
Объединяет прежнюю лекцию про стоимость AWS с новыми темами IAM и ML, закрывая курс:
- Shared Responsibility Model, основы IAM: пользователи, роли, политики, принцип наименьших привилегий.
- Модель ценообразования облака: on-demand/reserved/spot, факторы стоимости хранения и передачи данных.
- FinOps-практики: бюджеты, алерты, Cost Explorer/Billing reports, теговая стратегия для учёта расходов.
- Обзор облачных ML-платформ: SageMaker и Vertex AI (жизненный цикл модели, MLOps), где заканчивается Data Engineering и начинается Data Science в облаке.
- Итоговое обсуждение карьерных треков DE/DS в облачных командах.

### Детализация новых/изменённых работ

**Лаб. 1 (расш.) — AWS: консоль, IAM, EC2**
Цель: помимо запуска EC2 (как раньше), создать IAM-пользователя с ограниченной политикой (только EC2 read + start/stop), войти под ним и убедиться, что запрещённые действия блокируются. Это даёт первое ощущение принципа наименьших привилегий с первого занятия.

**Лаб. 3 — AWS VPC (новая)**
Цель: построить сеть вручную — создать VPC, публичную и приватную подсети, Internet Gateway, NAT Gateway, таблицы маршрутизации, Security Groups. Запустить EC2 в приватной подсети и подключиться к нему через bastion-хост в публичной подсети. Закрывает разрыв между теоретической лекцией про VPC и полным отсутствием практики.

**Лаб. 12 — Amazon Athena + S3 (новая)**
Цель: загрузить в S3 набор данных (CSV, затем тот же датасет в Parquet), создать таблицу через Glue Data Catalog или напрямую в Athena, выполнить SQL-запросы к «озеру данных», сравнить стоимость и скорость запроса CSV vs Parquet. Первое практическое знакомство с serverless-аналитикой.

**Лаб. 13 — AWS Glue: ETL (новая)**
Цель: с помощью Glue Crawler автоматически определить схему сырых данных в S3, написать простой ETL-джоб (Glue Studio или PySpark-скрипт) для очистки/трансформации данных и сохранения результата в другой бакет в формате Parquet, партиционированном по дате.

**Лаб. 14 — Amazon Kinesis (новая)**
Цель: создать Kinesis Data Stream, написать простой продьюсер (Python-скрипт, эмулирующий поток событий), подключить Kinesis Data Firehose для доставки данных в S3, опционально — Lambda-консьюмер для обработки событий в реальном времени.

**Лаб. 15 — Step Functions (доработана)**
Цель: вместо изолированного примера — собрать пайплайн, который запускает Glue-джоб, затем Lambda-функцию для валидации результата, с обработкой ошибок и retry-логикой. Показывает, как оркестрация связывает изученные сервисы в единый процесс.

**Лаб. 17 — CloudWatch + Cost Explorer/Budgets (новая)**
Цель: настроить CloudWatch Alarm на метрику EC2 (например, высокую загрузку CPU) с уведомлением через SNS; изучить Cost Explorer, построить отчёт по расходам за счёт тегов ресурсов; создать AWS Budget с оповещением при превышении лимита. Закрывает разрыв между лекцией про стоимость и отсутствием практики FinOps.

**Лаб. 19 — Google BigQuery (новая)**
Цель: загрузить публичный или собственный датасет в BigQuery, выполнить аналитические SQL-запросы, изучить партиционирование и кластеризацию таблиц, сравнить модель ценообразования BigQuery (оплата за объём сканируемых данных) с Athena. Даёт студентам параллельный опыт в экосистеме GCP для последующего сравнения.

**Лаб. 20 — Cloud Run + Firebase (объединение)**
Цель: развернуть контейнеризированное приложение в Cloud Run (как раньше) и подключить к нему Firebase (Firestore или Hosting) для хранения/раздачи данных — то есть не два изолированных занятия, а один связный мини-проект. Публикация статической страницы через GitHub Pages остаётся опциональным бонус-пунктом для тех, кто быстро справился.

## 3. Рекомендации по проведению

- **Синхронизация лекций и лабораторных**: каждая лекция должна на 1–2 занятия опережать соответствующие лабораторные работы (например, Лекция 5 «Хранение данных» — перед лабами 2, 3, 8, 9, 12).
- **Сквозной итоговый проект**: вместо (или в дополнение к) финальной ML-лабораторной предложите студентам собрать мини end-to-end пайплайн: источник данных → S3/GCS → Glue/Dataflow → Athena/BigQuery → простая визуализация (Streamlit/QuickSight/Looker Studio). Это свяжет лабы 2, 12, 13, 14, 15, 19 в единый практический навык и даёт материал для портфолио.
- **Единая «Rosetta Stone»-таблица AWS↔GCP** (из Лекции 3) стоит выдавать студентам как раздаточный материал и обновлять по ходу курса — так к финалу они смогут явно проговорить, чем Glue отличается от Dataflow, а Athena — от BigQuery.
- **Оценивание**: для DE/DS-трека имеет смысл добавить в критерии оценки лабораторных не только «сервис запущен», но и «данные корректно партиционированы/типизированы», «использованы теги для учёта стоимости», «IAM-права минимально достаточны» — это формирует правильные привычки с первого курса.
