Диск — это устройство постоянного хранения информации. Для хранения информации диску не нужно питание. Диск обеспечивает достаточно быстрый произвольный доступ к информации с небольшими задержками (в отличие от ленточных накопителей).

Информация на диске разбита на секторы одинакового размера. Типичный размер современного сектора 512b или 4kib. 

На первых жестких магнитных дисках (винчестерах) использовалась адресация секторов привязанная к физическим характеристикам (CHS - Cylinder, Head, Sector). Для указания сектора нужно было указать номер дорожки (Cylinder), номер считывающей головки (Head) и номер сектора (Sector). Поскольку эти характеристики варьировались в зависимости от конкретной модели диска от такой системы адресации быстро отказались в пользу LBA.

Адресацию секторов на дисках обеспечивает логическая адресация блоков (LBA - Logical block addressing). Типичная длина адреса сектора современных дисков — 32 или 48 битов.

Для использования диска нужно создать файловую систему.

Разделы на жестких дисках выровняны по целым мегабайтам.

Таблица разделов MBR / BIOS создана в начале 80-х годов. Максимум 4 первичных раздела (primary partition). Для загрузки ОС один из них можно пометить как активный (загрузочный). Для обхода ограничения в 4 раздела был придуман расширенный раздел. Один из первичных разделом может быть расширенным разделом. Внутри расширенного раздела (extended partition) можно создать до 32 логических дисков. Можно использовать только LBA32. Таблица разделов MBR размещается в первом секторе диска, сразу после первой стадии загрузчика ОС.

Таблица разделов GPT (GUID Partition Table). Создана для работы с UEFI. Максимум 128 разделов. Для загрузки ОС должна с UEFI должна содержать раздел специального типа: EFI System Partition (ESP). ESP всегда в формате FAT. GPT сохраняет свою резервную копию в конце диска.

Файловые системы
Журналируемые файловые системы — ведут журнал файловых операций перед модификацией данных, что повышает отказоустойчивость, но немного снижает производительность.

Обзор файловых системы поддерживаемых Linux:
●	ext, ext2, ext3, ext4
○	стабильная, журналируемая (ext3, ext4), нормальная производительность
●	btrfs была разработана в Oracle. Особенности:
○	многотомная файловая система (multivolume filesystem)
○	снятие снимков (snapshot) на лету
○	сжатие на лету
○	дефрагментация на лету
○	высокая производительность
○	контрольные суммы для проверки целостности хранимых файлов (checksums)
○	копирование при записи (copy-on-write)
○	продолжает разрабатываться, не стабильна
●	zfs была разработана в 2006 в Sun Microsystems для ОС Solaris. В данный момент ZFS поддерживается еще и в Linux и FreeBSD. Особенности:
○	многотомная файловая система (multivolume filesystem)
○	масштабируемость
○	копирование при записи (copy-on-write)
○	снятие снимков (snapshot) на лету
○	контрольные суммы для проверки целостности хранимых файлов (checksums)
○	дедупликация данных
○	проблемы с совместимостью лицензии CDDL и GPL
○	не развивается
●	xfs была разработана в 1994 в Silicon Graphics для ОС SGI IRIX, и была портирована на Linux в 2001. Особенности:
○	многотомная файловая система (multivolume filesystem)
○	масштабируемость
○	увеличение файловой системы на лету
○	хорошая производительность при работе с большими файлами
○	подходит для использование с SSD
○	журнал может быть отключен для повышения производительности
○	невысокая производительность при работе с большим количеством маленьких файлов
○	не развивается
●	jfs была разработана в IBM для ОС AIX в 1990 и позднее была портирована на Linux. Особенности:
○	хорошая производительность
○	увеличение файловой системы онлайн
○	масштабируемость
○	проблемы с совместимостью лицензии CDDL и GPL
●	reiser (reiserfs, reiser4) была разработана в 2001 (reiser4 — в 2004). Особенности:
○	высокая производительность (особенно при работе с маленькими файлами)
○	не развивается

Таблица разделов
Форматы таблицы разделов:
- MBR (Master Boot Record) - старый формат
  32-битная адресация секторов (до 2 Тбайт)
  4 основных раздела
  32 логических диска внутри расширенного раздела
  сложнее по структуре
  таблица разделов совмещена с загрузчиком ОС
- GPT (GUIDed Partition Table) - новый формат
  64-битная адресация секторов
  128 разделов
  загрузчики ОС находятся в специальном системном разделе (ESP)
- другие

Утилиты для работы с дисками:
- для работы с таблицей разделов
  - fdisk
  - parted / gparted
- для создания файловой системы (форматирование)
  - mkfs
- для проверки файловой системы
  - fsck
- для измения размера файловой системы:
  - resize2fs
- для тонкой настройки параметров ФС
  - tune2fs
- для монтирования файловой системы к дереву каталогов
  - mount
- для размонтирования ФС
  - umount
- для проверки дисков на сбойные сектора
  - badblocks
- для проверки данных S.M.A.R.T.
  - smartctl
- для уничтожения данных
  - shred

Стандарты контроллеров для подключения дисков
- Parallel ATA (PATA, IDE)
- Serial ATA (SATA)
  - SATA3 6 Gib/s примерно 5xx MiB/s
- SCSI
- Serial attached SCSI (SAS)

Разъемы подключения SSD - Solid State Drive:
- SATA (чтение не более 600 МiB/s)
- M2
  - SATA
  - NVMe (чтение более 2 GiB/s)

RAID - Redundant Array of Independent Disks
технология объединения нескольких дисков в логически единый массив
+ повышение производительности дисковой подсистемы
+ повышение надежности хранения данных
- высокая стоимость
